Native interrupt return

RTI restores the nine-byte context CCR,B,A,Xhi,Xlo,Yhi,Ylo,PChi,PClo and
advances SP by9 with16-bit wrapping. Numeric D is A:B, so restoring the saved
B:A word exchanges its bytes. The stacked X mask cannot raise an initially
clear X; all other CCR bits are restored.

Logical reads follow the manual's CCR,B:A,X,PC,Y order. Full known RAM has
no owner calls or host frame. Partial/external storage uses a16-byte host
frame to stage values; CPU registers commit only after every real read is
accepted. A refused access retains actual callback effects and leaves every
CPU register unchanged. Fault latching prevents automatic replay. A word
crossing a known/unknown seam delegates one complete logical wide access.

Authored tests cover all stack positions, all values of each word destination,
every old/saved CCR combination, a literal frame, exact bus order/width,
faults at every phase, fresh-boundary recovery and a fetched RTI-to-NOP path.
These return tests alone do not establish interrupt recognition, WAI reuse,
tail chaining, event priorities, clocks or full original firmware operation.

Interrupt entry

Core::interrupt_ready(kind) tests the current I/X mask and the maskable-IRQ
transition delay. The caller chooses the highest eligible source/vector and
owns acknowledgement and device time. Core::interrupt(request) reads the
actual vector, then writes returnPC,Y,X,B:A,CCR on the real stack. SP decreases
by9; I is set, and X is additionally set for XIRQ. Other registers remain intact.
The return PC is the genuine next instruction, without an injected routine call.

Entry compiles as a distinct native event in the same bounded W^X cache. Known
RAM needs no host frame/callback. External transactions stage the vector target
and publish CPU state only after every access succeeds. Actual partial writes
are preserved on failure; the fault latch prevents replay. A masked/deferred
request has accepted=false/fault=none and performs no access or acknowledgement.
Entry retires no firmware instruction. The event cache domain is distinct from
captured-byte instruction keys.
EventResult.pc identifies the original boundary, while registers().pc exposes
the accepted vector target.

ANDCC and TAP that change I from1 to0 defer maskable recognition until one
following instruction retires. Only those native instructions arm the bounded
counter; XIRQ ignores that delay. Cache clearing retains it, while an explicit
fresh register/reset boundary clears it. No new delay is inferred for other
CCR-destination transfers; their timing remains a separate research corner.

This is an explicit entry/readiness interface. wait.txt specifies native wait
frames and wake reuse; checkpoints.txt specifies CPU-only snapshots. It does not
arbitrate pending sources during run() or supply
board-cycle timing. The board must call entry at qualified instruction
boundaries and coordinate vector acknowledgement with actual bus effects.
tail-chain.txt specifies the native post-RTI entry mode and the board's frame
availability query. Ordinary entry, wait wake and return reuse have distinct
cached code for the same source/vector.
