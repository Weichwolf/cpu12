Fetched native execution

step() captures the current instruction from the borrowed RAM window or the
explicit Io.fetch byte callback, then executes the same native JIT used by
run_instruction(captured_bytes). Code fetch never falls back to data read or
word callbacks. Io is copied at construction; its owner and RAM remain alive.
Callbacks are noexcept and obey the same single-owner/reentrancy restrictions
as data accesses. Statistics records actual external fetch_callbacks separately.

The logical fetch reads exactly the selected instruction bytes in order, with
16-bit address wrapping. It stops after an unknown opcode/page or an excluded
indirect postbyte. Supported opcode-length plans are derived once from our
decoder at first use. Indexed postbytes select their actual
extension width. No ISA decoder runs for a warm captured cache entry. Code is
fetched again at each instruction boundary; the complete actual bytes/length
form the native cache key. Guest stores and externally changed mappings therefore
cannot silently reuse stale opcode lengths, operands or host code.

A refused/missing code callback produces Fault::instruction_fetch with the
original instruction PC/opcode, failing byte address/value and access_size=1.
Before a successful first-byte fetch, opcode is zero. Registers/PC and retirement
remain unchanged; real fetch effects already performed remain visible. Every
fetched-instruction fault, including unsupported ISA, latches until explicit
set_registers. Cache invalidation cannot replay code or data effects. The
captured API retains its existing unsupported-input contract. Cold JIT setup
may allocate or throw; callers must establish a fresh boundary before retrying
a failed setup after real fetch effects.

run(instruction_budget) stops after that many completed instructions or the
first fault. RunResult.retired counts only instructions completed by this call;
pc/opcode identify the last attempted instruction, not the final register PC.
A later call at a latched fault returns zero retirements. A zero budget performs
no fetch or execution. This is an instruction budget, not a cycle/time budget.

This is a logical byte-fetch model, not the physical CPU12 prefetch queue or
bus-cycle timing. Reset and native interrupt events have separate interfaces;
run() does not arbitrate sources or advance board time; it exits at real idle
boundaries without further fetching. Native regions,
event/cycle budgets and Blofeld integration remain required work. Tests use an independent literal
opcode/length catalogue, explicit indexed postbyte sets and authored programs;
they establish neither original firmware execution nor real-time throughput.
