Native indexed addressing and effective-address operations

The captured entry accepts up to four bytes. Complete captured bytes and length
identify a native cache entry; base registers and PC remain dynamic. Decoding
runs only on a cache miss. Invalid prefixes or excess zero padding cannot reuse
a valid native entry. The frontend never replaces unsupported instructions.

Implemented memory opcodes support all 256 indexed postbytes: signed 5-/9-bit
and wrapping 16-bit constants, unsigned A/B/D offsets, constant/D indirect
pointers, and X/Y/SP pre/post changes from -8..-1 or 1..8. PC denotes the
address after the complete instruction. LEAX/LEAY/LEAS support all 248 legal
nonindirect postbytes without data accesses or CCR changes. Indirect LEA
refuses explicitly. Remaining ISA, waits, cycle timing and board integration
are open.

Pre-update selects the adjusted base address; post-update selects the old one.
The operation reads adjusted register sources. A loaded destination can replace
its index update. LEA receives the effective address, so overlapping
post-update is not retained. S12CPUV2 section 3.9.5 and the LEA entries
document the address rules and LEA overlap. Separately authored SLEIGH
observations corroborate the load/store/compare overlaps; this is not a
measured silicon claim.

Generated x64 computes addresses and accesses known RAM directly. A full 64-KiB
layout omits impossible bounds checks; partial windows check both word bytes.
Words and indirect pointers are big-endian and wrap from ffff to zero. A
partial RAM word delegates its complete logical request, including known RAM
portions, to the supplied owner. Indirect access reads the pointer before its
operand. Only genuine external accesses call the real noexcept bus callbacks.

A rejected access leaves CPU/index registers at the original unretired
boundary. Accepted external effects remain real, including an adjusted-source
store that then refuses. Callbacks see that original CPU boundary. CPU updates
publish only after accepted data access, and a latched fault prevents replay.
Diagnostic PC, opcode, address and width identify the failing pointer/operand
phase. This is an explicit synchronous functional API, not physical bus-error
rollback.

The earlier native auto/LEA integration passed 292732 cases and five existing
consumers, including 168432 non-auto indexed cases, on one coherent library.
transfer-reference.json records current consumers after register transfers.
All CCR values, destination/source overlap, wrapping, indirect effects, cache
length collisions and latched refusals have independent
expectations. auto-indexed-reference.json pins that integration's source, ELF
and actual run receipts. Historical indexed-reference.json retains its separate source
pins. Four SMT queries prove interval/wrap/PC arithmetic, with two SAT negative
controls; LLVM decoding separately checks the emitted host instruction
encodings. These are component checks, not full ISA, original boot, instrument
or realtime acceptance. No fuzzing was run; extensive sanitizer work remains
deferred under the real-time-first development policy. reference-manifest.json
pins the manual.
